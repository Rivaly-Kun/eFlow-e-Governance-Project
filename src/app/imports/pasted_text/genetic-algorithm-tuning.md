Genetic Algorithm TuningThis section provides the IT Administrators with a visual control panel to manipulate the evolutionary algorithms responsible for workload distribution across the municipality's project teams.1.1 Fitness Function VariablesPage Header & Actions: "Fitness Function Configuration." Top-right actions include "Save Variable Preset", "Load Previous Preset", and "Reset to Default".Main Content Area: A highly structured configuration board designed to replace raw code editing. Rows represent the specific mathematical variables the algorithm uses to judge a "good" task assignment (e.g., Task Deadline Proximity, Employee Idle Time, Required Skill Match). Columns include "Variable Name", "Data Type", an active "Status Pill" (Included/Excluded), and a "Weight Multiplier" numbers column where admins can manually type the mathematical weight.Widgets/Visualizations: A dynamic Radar Chart updating in real-time as the admin adjusts the Weight Multiplier column. It visually maps the balance of the fitness function (e.g., showing if the algorithm is heavily skewed toward "Speed" versus "Cost Efficiency").1.2 Workload WeightingPage Header & Actions: "Workload Distribution Weights" and a prominent "Run Weighting Simulation" button.Main Content Area: A Split-View layout. The left pane features interactive sliders to assign penalty weights to specific conditions (e.g., a slider to heavily penalize the algorithm if it attempts to assign a task to an employee already working 40 hours). The right pane displays a dynamic Gantt-style timeline showing a mock project allocation based on the current slider weights, instantly updating to show how the changes affect team capacity.Widgets/Visualizations: A comparative bar chart showing "Projected Average Idle Time" versus "Historical Average Idle Time," visually validating the efficiency of the weighting adjustments.1.3 Competency MappingPage Header & Actions: "LGU Competency Matrix." Actions include "Import HR Data" and "Add Skill Tag".Main Content Area: A Kanban board grouping technical skills by LGU Department (e.g., "Engineering," "Health," "Finance"). Cards represent specific certifications or skills (e.g., "AutoCAD," "COA Audit"). Clicking a card opens a right-side drawer (progressive disclosure) listing the specific employees possessing that skill and their proficiency level, which the Genetic Algorithm queries before assigning complex tasks.Widgets/Visualizations: A Donut Chart showing the distribution of specialized skills across the LGU workforce, helping IT and HR immediately spot skill shortages that might bottleneck algorithmic task assignments.1.4 Local Optima PreventionPage Header & Actions: "Evolutionary Stagnation Controls" and a "Test Convergence" action button.Main Content Area: A dense, technical settings board. Columns are dedicated to "Mutation Probability" (a slider ranging from 0.01 to 0.10) and "Crossover Strategy" (a dropdown allowing the selection of Single-point or Multi-point crossover). This ensures the algorithm continues to find highly efficient schedules during peak infrastructure deployment seasons.Widgets/Visualizations: A Rickshaw Area Chart tracking fitness progression over 1,000 simulated generations. If the line flatlines too early (indicating the algorithm is trapped in a local optima), the chart pulses yellow to warn the administrator to increase the mutation rate.2. Predictive Analytics EngineThis section manages the machine learning models (like Random Forests and Neural Networks) that forecast project delays and predict employee burnout before they happen.2.1 Burnout ClassifiersPage Header & Actions: "Burnout Risk Classifiers." Actions include "Retrain Classifier Model" and "View Confusion Matrix".Main Content Area: A dynamic list view tracking the specific parameters used by the Random Forest model to predict burnout. Rows represent input features (e.g., cumulative overtime hours, task delays, leave credit depletion). Columns show "Weight", a "Data Drift Status" pill (Stable in Green, Drifting in Red), and "Last Synced Timestamp."Widgets/Visualizations: An ROC-AUC curve visualization to display the model's mathematical accuracy in predicting true positives for burnout risk. A "Battery" widget summarizing the overall accuracy score of the current model version (e.g., 88%).2.2 Project ForecastingPage Header & Actions: "Timeline Prediction Models", "Run Global Forecast", and "Export to Executive Dashboard".Main Content Area: A forecasting board grouped by major city portfolios (e.g., Infrastructure, Healthcare). Rows are active projects. Columns include "Current Status", "AI Predicted Completion Date" (a formula-driven date column), and "Risk of Delay" (a high-contrast status pill: Low, Medium, High).Widgets/Visualizations: A Scatter Plot comparing planned project delivery dates against the AI's predicted delivery dates. Projects that are statistically highly likely to miss their deadlines appear as pulsing red dots far above the trendline.2.3 Confidence IntervalsPage Header & Actions: "Model Confidence Thresholds" and "Adjust Error Margins".Main Content Area: A threshold configuration board. This relies on a slider UI pattern to set acceptable confidence limits for AI predictions. If a prediction's confidence falls below the set percentage (e.g., 75%), it triggers a rule in an Automation Column that flags the prediction for human validation.Widgets/Visualizations: A Confidence Band Chart visualizing the uncertainty margin for budget overrun predictions over the next 12 months, using translucent shading around the trendline to represent the statistical margin of error.2.4 Feature ImportancePage Header & Actions: "Predictive Feature Analysis" and "Recalculate Weights".Main Content Area: A ranked table view acting as an "Explainable AI Overlay". It shows exactly which variables are driving the AI's predictions. Columns include "Feature Name", "Impact Score" (a numbers column utilizing a horizontal progress bar visual within the cell), and "Correlation Direction" (a tag indicating Positive or Negative correlation).Widgets/Visualizations: A horizontal bar chart prominently displaying the top 10 most influential features. If "Unliquidated Cash Advances" suddenly jumps to the top of the chart, the IT admin understands exactly why the AI is forecasting project delays.3. NLP Engine DiagnosticsThis section monitors the health of the Natural Language Processing pipelines that ingest unstructured data from employees (like voice notes and Viber messages) and turn them into structured project updates.3.1 Stand-Up IngestionPage Header & Actions: "Daily Stand-Up Logs" and "Re-run Extraction Pipeline".Main Content Area: An inbox-style Kanban board tracking the raw inputs from LGU staff. Columns show the processing stages: "Raw Input", "Entity Extraction", "Summarized", and "Failed Parsing". Cards contain the employee's avatar, a snippet of their raw text, and a "Parsing Status" pill.Widgets/Visualizations: A line chart tracking the daily volume of stand-up submissions across departments to monitor system adoption. A donut chart showing the distribution of identified intents (e.g., 60% Task Updates, 30% Blocker Alerts, 10% Clarifications).3.2 Voice-to-Text PipelinePage Header & Actions: "Audio Transcription Health" and "Update Regional Dialect Lexicon".Main Content Area: A Split-View layout specifically designed for audio debugging. The left side lists audio files sent by field workers. Clicking a row opens the right side, which features an embedded audio player, the AI's raw text transcription, and an editable text box. If the AI misinterprets a regional dialect , the admin can manually correct it here, feeding the correction directly back into the model's training data.Widgets/Visualizations: A "Transcription Accuracy" gauge widget, aiming for $>95\%$ accuracy. A secondary line chart tracking the share of out-of-vocabulary (OOV) words over time. A spike in this chart serves as a visual alert that the model needs its dictionary updated.3.3 Viber Chatbot HealthPage Header & Actions: "Viber Integration Status", "Test Webhook", and "View API Logs".Main Content Area: An infrastructure monitoring board specifically for the Viber API connection. Rows represent API endpoints or webhook listeners. Columns include "Uptime", "Average Latency" (Numbers column in milliseconds), "Payload Size", and a strict Status Pill (Healthy, Warning, Down).Widgets/Visualizations: A real-time traffic graph showing the velocity of incoming messages from citizens and field workers versus outgoing automated replies. This helps IT spot sudden bottlenecks or API throttling during peak hours or city-wide emergencies.
