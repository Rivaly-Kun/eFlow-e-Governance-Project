# Product & UX North Star

## Product definition

eFlow is a local-government work-management and execution platform.

Its strongest product identity should be:

> A productivity workspace for executing, coordinating, reviewing, and auditing government work.

## UX correction

Do not design eFlow primarily as an analytics dashboard or a generic government admin portal.

The central experience should be **work itself**:

- projects
- milestones/groups
- tasks
- owners
- departments
- status
- due dates
- priority
- evidence
- reviews
- comments/activity
- filters
- search
- sorting
- grouping
- drill-down

## Target interaction model

Think:

**monday.com productivity workspace**
+
**eFlow government workflows, permissions, evidence, review, accountability**

The UI may strongly resemble the interaction density and work-management clarity of monday.com while retaining eFlow-specific identity and business rules.

## Primary workspace anatomy

A strong eFlow workspace often looks like:

Project / workspace identity

View tabs

Action toolbar:
- Add task
- Search
- Person / owner
- Filter
- Sort
- Hide / columns
- Group by
- More

Grouped work table:

Group / Milestone
→ Task rows
→ Owner
→ Status

→ Due date
→ Department

Click task title
→ Task Detail surface
→ description

→ evidence
→ review history
→ activity
→ workflow actions

## Dashboards

Dashboards are secondary.

Their job is to answer:
- What needs attention?
- What should I open?
- What work is overdue?
- What requires review?
- Which projects need attention?

A dashboard should route users into real workspaces.

Do not let KPI cards define the visual language of the whole product.

## Productivity-first rules

Prefer:
- tables
- grouped rows
- work boards
- views
- filters
- inline metadata
- contextual menus
- drawers/dialogs
- visible ownership
- fast navigation

over:
- giant cards
- decorative graphs
- isolated KPI widgets
- large empty dashboards
- "portal" layouts

## Creativity

The coding agent has creative freedom.

It may use:
- Vibe components
- strong status treatments
- colored group accents
- compact cards when appropriate
- sticky work toolbars
- responsive workspaces
- subtle motion
- rich hover/focus states
- side panels
- split panes
- dense tables
- intentional empty states

The quality bar is not "looks consistent."

The quality bar is:

> This feels like a real professional productivity application.
