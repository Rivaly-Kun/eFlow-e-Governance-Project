# eFlow UX Writing Standard
## Based on the Vibe UX Writing Handbook

Apply this to every user-facing string during migration.

## Principles

### Clarity
Use simple language.
Avoid technical jargon.
Keep copy short and direct.

### Consistency
Use stable product terminology across all roles and workspaces.
Format similar message types consistently.

### Accessibility
Use inclusive language.
Prefer familiar words and short sentences.

## Personality

eFlow should feel like a capable assistant.

### Expert and reliable
Communicate with reassuring confidence.
Own errors.
Explain the next useful action.

### Proactive and supportive
Anticipate what users need without overwhelming them.

## Voice

### Empathetic and conversational
Human-to-human.
Direct.
Respectful.

### Positive and professional
Use affirmative language.
Stay professional in government/accountability workflows.

## Tone

Use lighter tone for:
- empty states
- onboarding
- low-risk guidance

Use professional/reliable tone for:
- errors
- review decisions
- budget/fiscal actions
- project activation
- evidence
- archive/delete
- permissions
- audit-sensitive flows

## Golden rules

### Bottom line first
Start with the most important information.

### Give full context
Users should know what item/action a message refers to.

### Focus on the user's point of view
Write around the user's goal, not implementation internals.

### One primary CTA
Avoid competing primary actions.

### Use specific CTAs
Prefer:
- Add task
- Start work
- Submit for review
- Review submission
- Request changes
- Approve submission
- Upload evidence
- Add approved project
- Activate project
- Archive project

Avoid vague:
- OK
- Proceed
- Manage
- Submit
- Confirm

### Cut the fluff
Every sentence should help understanding, confidence, or action.

## eFlow terminology

Use consistently:
- Project
- Milestone
- Task
- Subtask
- Evidence
- Submission
- Review
- Department / Office
- Project responsibility
- Task responsibility

Do not expose:
- UUIDs
- raw database codes
- backend status strings
- implementation terminology

unless explicitly needed by an administrator.

## AI

AI-generated execution content is provisional.

Never write copy that makes generated content sound automatically authoritative.

Example:

> Review the generated plan before activation. Confirm tasks, departments, dates, and responsibilities.
